## 定义

把在缓解关闭、未启用、仅审计或仅部分覆盖的目标上取得的成功，误认为默认加固配置下的成功。另一种情形是把依赖未披露前提的绕过步骤误认为无条件绕过。缓解状态是按进程、按模块、按构建配置生效的前提，必须与结果一起取证和披露。

## 示例

演示环境关闭地址随机化以获得确定性，利用成功，报告写“目标缓解可被绕过”。同一流程未在默认启用随机化的目标上重跑。证据支持的是：无地址随机化条件下链可成立；对该缓解的绕过能力未被证明。两种结论必须分开表述。

## 识别方法

- 建立缓解项与目标制品的矩阵，逐项标注启用、关闭、仅审计、部分覆盖或未知，并列出与厂商默认加固配置的差异。
- 取证对象是制品与运行时状态，不得以描述代替证据：二进制头与加载配置、编译与链接选项、进程缓解策略、内核构建配置与启动参数、沙箱配置。
- 检查覆盖率：哪些模块、进程与代码路径实际受保护。
- 检查绕过步骤及其前提：是否依赖独立的泄露、写原语或合法目标复用。
- 最小证伪：在默认加固配置的目标上重跑同一流程；失败则原结论降级为条件结论。

## 预防与验收要求

- 必须为每个利用结果附缓解状态表，逐项给出状态、覆盖范围、覆盖率与证据来源。
- 不得在未声明的情况下关闭、降级或绕过缓解。关闭操作必须作为独立实验条件，与默认配置结果分开报告。
- 必须把绕过步骤计入链阶段（见 VXP-017），并披露其自身前提与所需能力。
- 必须区分“关闭缓解”与“绕过缓解”：前者改变目标状态，后者保留缓解但引入额外前提，二者不得混写。
- 不得把仅在无缓解或部分缓解目标上成立的结果表述为对该缓解的通用绕过。

## 验收证据与量化字段

- 缓解状态表及每项的证据来源（制品字段、构建记录、运行时策略、配置文件）。
- 覆盖率数据：启用缓解的模块或进程清单及总数。
- 演示配置与厂商默认配置的差异清单。
- 每个绕过步骤的独立证据及其前提清单。
- 默认加固配置下的重跑记录，或明确声明“未在默认配置下验证”。

| 缓解项 | 状态 | 覆盖范围 | 证据来源 | 绕过步骤数 | 绕过前提 |
|---|---|---|---|---|---|
| 地址随机化 | 启用/关闭/部分/未知 | 进程或系统 | 配置或运行时查询 | 0..n | 列表 |
| 数据执行保护 | 启用/关闭/未知 | 进程 | 二进制头或策略 | 0..n | 列表 |
| 控制流保护 | 启用/关闭/部分 | 模块清单 | 加载配置或构建选项 | 0..n | 列表 |
| 栈保护 | 启用/关闭/部分 | 模块清单 | 构建选项 | 0..n | 列表 |
| 沙箱或权限隔离 | 启用/关闭/放宽 | 进程或服务 | 配置文件 | 0..n | 列表 |

下表为本项目约定的记录结构，具体缓解项由项目按目标平台补充；本条不规定必须启用哪些缓解。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `mitigation` | 被评估的缓解项名称 | 文本 |
| `state` | 该项在目标上的实际状态 | 枚举：启用 / 关闭 / 仅审计 / 部分 / 未知 |
| `coverage_ratio` | 受该缓解保护的模块或进程数占总数的比例 | % |
| `evidence_source` | 状态的取证来源 | 枚举：二进制字段 / 构建选项 / 运行时策略 / 配置文件 / 厂商文档 |
| `bypass_steps` | 绕过该项所需的独立步骤数 | 个 |
| `bypass_preconditions` | 绕过步骤各自的前提清单 | 列表 |
| `default_config_match` | 演示配置是否与厂商默认加固配置一致 | 枚举：是 / 否 / 未知 |

## 边界与关联

- 为隔离变量而关闭缓解是合理的研究手段；本条要求披露关闭状态。
- 地址随机化等统计性缓解的状态不止开与关，可记为“部分”，并另记量化依据（熵或覆盖范围）。本条不设具体强度门槛。
- 绕过不等于关闭：绕过保留缓解开启，但引入信息获取或合法目标复用等前提。两者都须披露，结论措辞不同。
- 本条只评价状态与前提是否被如实记录，不评价缓解是否足够强。通过本条检查后，默认配置下是否可利用仍需版本绑定与攻击面核实（见 VXP-002、VXP-003、VXP-004）。
- 与 VXP-003 的边界：非缓解类配置值的默认配置被当作生效配置属该条。与 VXP-033 的边界：旧版本的缓解状态不得套用到新构建。
- 无子条目。
