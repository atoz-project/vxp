## 定义

把已发布的“可利用性声明”误认为漏洞已被验证或已被修复。另一种误读是把未声明的状态读成不受影响。

声明单元是产品、漏洞、状态与时间的四元组。状态取 not_affected、affected、fixed、under_investigation。not_affected 必须给出机器可读理由码或影响说明。affected 应给出处置动作。状态供自动化消费，不是成功证明。验收结论仍须绑定具体制品与证据。

## 示例

扫描器在构建中检出某组件版本，供应商声明 not_affected，理由为 component_not_present。验收方据此关闭条目。错误结论：已验证该构建不受影响。证据支持的结论：声明针对另一制品，当前构建的组件清单与哈希未核对。

## 识别方法

- 检查声明是否同时给出产品标识（包 URL、哈希或版本）、漏洞标识、状态与时间。
- 检查状态是否属于四个标准值，以及 not_affected 是否附理由码或影响说明。
- 检查 affected 是否给出处置动作，以及 fixed 是否指向包含修复的制品。
- 检查声明针对的制品与本项目验收的制品是否同一，哈希或包 URL 是否一致。
- 检查同一产品的多条声明是否有版本与时间顺序，旧状态是否可追溯。

## 预防与验收要求

- 每条声明按四元组记录，状态变化保留旧版本与时间。
- not_affected 必须使用机器可读理由码。自由文本说明作为补充，不替代理由码。
- 供应商声明只作输入，验收结论必须绑定本项目制品标识与检查记录。
- 不得把 affected 或 under_investigation 读成失败结论，也不得把 fixed 读成利用已不可能。
- 理由码集合由项目约定。本条目采用 VEX 的四个状态名，不引入分数或阈值。
- 声明与证据冲突时以证据为准，并记录冲突。

## 验收证据与量化字段

最小证据：声明原文与版本；产品标识与哈希；理由码或影响说明；声明时间；本项目制品与声明的对应记录。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `vex_status` | 声明给出的可利用性状态 | `not_affected` / `affected` / `fixed` / `under_investigation` |
| `justification_present` | not_affected 是否附理由码或影响说明 | `yes` / `no` / `not_applicable` |
| `product_identifier_bound` | 声明制品与验收制品的标识是否对应 | `yes` / `partial` / `no` |
| `statement_versioned` | 声明是否带版本或时间并可追溯 | `yes` / `no` |

## 边界与关联

- 与 VXP-042 的分工：042 检查工作流状态；本条目检查标准化声明及其理由码。
- 与 VXP-041 的分工：研究任务完成或证伪后，不因声明为 affected 就成为漏洞交付。
- 与 VXP-034、VXP-036 的分工：依赖是否声明、环境能否重建，不在本条范围。
- VEX 状态不是严重性分数，也不是优先级。威胁情报只作背景。
- 无子条目。
