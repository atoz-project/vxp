## 定义

把单个进程或组件内部的效果误认为对该主机、服务或外部系统可交付的终局。进程内效果受该进程的权限、命名空间、沙箱、生命周期与输入通道约束；它不自动转化为文件系统写入、服务行为改变或对其它主体的控制。

终局指验收合同要求最终成立且可观察的效果。进程退出、重启或隔离边界重建后即消失的效果，不能支撑主机级或服务级结论。

## 示例

PoC 打印出受控的指令指针，报告称“获得主机控制权”。证据只说明该进程内控制流可被影响；进程退出后效果消失，也没有主机侧的独立观测。

限定例外：合同目标就是“使该服务返回错误”或“读取该进程持有的密钥”。此时进程内效果可以作为终局，但结论必须限定在该服务行为或该进程可访问的数据。

## 识别方法

- 对每条效果标注四件事：作用域、执行身份、是否越过强制边界、进程退出后是否仍成立。
- 检查终局证据的采集者：独立进程或主机读取文件、服务响应改变、连接建立、审计记录出现。利用进程自己写入再自己读取的记录不算。
- 做最小证伪：重启目标进程后在同一入口重测。效果消失且无外部残留时，不能称为外部终局。
- 检查用词是否区分原语、效果与终局，三者是否被混写。
- 若声称跨边界，要求边界两侧的观测，而不是只在边界内侧观察。

## 预防与验收要求

- 能力声明必须把原语与终局分列；终局必须由不受利用程序控制的通道确认。
- 不得用进程内状态推断主机级、服务级或网络级结果；跨边界主张必须附边界穿透证据。
- 必须标注作用域与执行身份；作用域不明时按最保守范围表述。
- 效果依赖调试器、插桩或非默认启动参数时，必须显式限定，不得写成默认形态。
- 限定例外只有在合同目标本身限于该进程时才成立，并须写明目标边界与观测方式。

## 验收证据与量化字段

最小证据：

- 作用域与执行身份标注。
- 边界穿透证据：例如进程内写入后由边界外的主体独立读到同一内容。
- 与利用进程分离采集的终局观测记录。
- 进程退出或重启后的复测记录。
- 原语到终局的转化步骤说明，逐步对应证据。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `effect_scope` | 效果实际发生的作用域 | `process` / `container` / `vm` / `host` / `network` |
| `exec_identity` | 效果发生时进程的主体身份类别 | 字符串 |
| `boundary_crossed` | 效果是否越过某个强制隔离边界 | `none` / `process` / `container` / `vm` / `host` |
| `persists_after_exit` | 目标进程正常退出后效果是否仍可观测 | 布尔 |
| `outcome_observer_independence` | 终局观测者相对利用程序的控制关系 | `out_of_band` / `target_audit` / `in_band` / `self_reported` |
| `observer_under_attacker_control` | 观测通道或观测者是否受利用程序控制 | 布尔 |
| `transformation_steps` | 从原语到终局所需的独立转化步骤数 | 整数 |

`observer_under_attacker_control` 为真时，该观测不得计为外部观测，无论采集位置在同一主机还是远端。

## 边界与关联

目标本身是进程内行为时，进程内效果可以作为终局，但必须限定影响范围；这不是外部终局主张。进程内任意读在“目标仅是读取该进程持有的密钥”的威胁模型下也可以是完整终局。

通过本页检查只能证明范围描述与观测一致，不能证明效果在其它部署形态下成立。域归属判错见 VXP-021，类别外推见 VXP-023。
