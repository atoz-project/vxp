## 定义

把在某一制品形态或构建配置上取得的实证误认为对默认交付形态同样成立。实证是存在性命题，只对被测试的制品成立。版本号相同不等于制品相同。

构建配置会改变与可利用性相关的属性：优化级别影响内存布局与未定义行为，调试信息与断言改变时序和失败方式，sanitizer 与插桩改变分配和调度，链接方式与打包补丁改变依赖和代码路径。

## 示例

在本地 `-O0` 构建的二进制上触发崩溃，交付物是启用优化与 hardening 的发行版安装包。报告写“版本 X 可触发”，但没有在交付形态复跑，也没有判定两种构建的差异。

另一例：实证脚本从源码目录直接运行，交付物通过服务入口启动；工作目录、权限、环境变量与入口脚本都不同，报告没有说明结论适用于哪个对象。

## 识别方法

- 索取并比对两个摘要：实证实际执行的制品与默认交付制品，两者使用同一算法。明确每个摘要覆盖的对象是单文件、安装包、镜像还是文件系统。
- 检查构建与打包差异：优化级别、调试信息、断言、sanitizer、编译宏、链接方式、strip、签名、发行版补丁、入口脚本。
- 检查运行路径差异：解释器或运行时版本、依赖解析位置、启动用户、工作目录、环境变量、启动参数。
- 检查版本绑定：版本标识是否由制品内容派生，还是仅来自文件名、目录名或发布说明。
- 最小证伪：把同一实证脚本指向交付制品（先核对摘要一致）复跑；无法复跑时，报告必须标注结论适用范围。

## 预防与验收要求

- 必须分别记录实证制品与交付制品的密码学摘要、摘要算法与摘要对象；不得只用版本号或文件名指代制品。
- 声称结论适用于交付形态时，必须在交付形态复跑，或提供可核查的等价性论证：构建配方、逐项配置差异、差异对相关代码路径的影响判定。
- 不得把调试、插桩或源码直跑形态的结论无标注地外推到发布形态。
- 构建配置应当由版本控制中的配方定义，并与实证配置可逐项比较。本项目约定：差异必须列全并逐项判定影响，不设统一允许项。
- 实证制品与交付制品无法对齐时，验收结论必须降级为“仅在实证形态成立”，并保留该限定语。

## 验收证据与量化字段

最小证据：

- 两种制品的摘要值、摘要算法、计算对象和计算时间。
- 两种形态的构建配方或配置快照：工具链及版本、关键编译与链接标志、补丁列表、打包与签名步骤。
- 在交付形态上的复跑原始输出、退出码与时间；或逐项差异影响分析及其依据。
- 版本到制品摘要的绑定记录，例如发布清单、签名或构建来源证明。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `tested_artifact_digest` | 实证实际执行的制品内容摘要 | 十六进制字符串 |
| `delivered_artifact_digest` | 默认交付制品的内容摘要，使用同一算法 | 十六进制字符串 |
| `digest_scope` | 摘要覆盖对象 | 单文件 / 安装包 / 容器镜像 / 文件系统镜像 |
| `build_profile_tested` | 实证制品的构建配置标识 | 字符串（如 debug、release、distro-package） |
| `build_profile_delivered` | 交付制品的构建配置标识 | 字符串 |
| `config_delta_items` | 两者之间已识别的构建或打包配置差异项数 | 项 |
| `delta_items_assessed` | 已给出书面影响判定的差异项数 | 项 |
| `rerun_on_delivered` | 是否在交付形态上复跑 | 是 / 否 / 不适用 |

## 边界与关联

合理例外：研究目标明确限定为源码级缺陷存在性，报告通篇声明不针对任何交付形态；此时仍不得用交付版本的版本号给结论命名。

运行环境替代见 VXP-007；目标系统上默认配置被当作生效配置的口径见 VXP-003。本条只证明结论已在所验交付形态上成立，或已按披露规则保留形态限定，不证明其它形态同样成立，也不证明构建过程可信。证据与代码版本的时间绑定见 VXP-033。
