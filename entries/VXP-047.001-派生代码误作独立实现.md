## 定义

把 fork、复制或改写自同一 upstream 的 PoC 误认为独立实现，用同源多份结果充当交叉验证。谱系独立指代码来源，执行独立指由谁运行，两者不可互换。

## 示例

两个仓库的 PoC 结构相同，报告称“两个独立来源均成功”。复核显示二者是同一 upstream 的 fork，只改了输出文案。错误结论：交叉验证成立。证据支持的结论：同一实现被运行两次，共同缺陷仍可能存在。

## 识别方法

- 查 upstream 链接与 fork 关系，确认仓库是否由同一源派生。
- 比对文件哈希与差异行，判断共享代码的范围。
- 查看首次提交时间与作者，识别短期复制或批量镜像。
- 检查修改是否触及触发路径，还是只改日志文案、参数名或输出格式。
- 若声称独立实现，检查是否给出无共享代码的依据。

## 预防与验收要求

- 交付记录 upstream、fork family 与修改点；派生件标注为派生。
- 不得把同源多份 PoC 计为独立证据。
- 独立实现声明必须附依据，例如无共享代码的比对结果；判断方式由项目约定。
- 引用他人 PoC 时保留原始出处与修改记录。
- 谱系不明时标为 unknown，按未知来源处理。

## 验收证据与量化字段

最小证据：upstream 与 fork 说明；文件哈希与差异清单；首次提交时间与作者；独立实现声明的依据。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `lineage_type` | 与 upstream 的关系 | `original` / `fork` / `unknown` |
| `upstream_recorded` | 是否记录 upstream 与修改点 | `yes` / `no` |
| `diff_scope` | 修改落在触发路径还是仅输出层 | `trigger_path` / `output_only` / `unknown` |
| `independence_claim` | 独立实现主张的证据支持程度 | `supported` / `partial` / `unsupported` |
