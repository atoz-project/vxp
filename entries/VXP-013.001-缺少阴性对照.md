## 定义

把无阴性对照的观测当作效果。阴性对照的作用是证明观测量能区分处理条件与基线条件。缺少阴性对照时，环境预置、默认配置、缓存、工具误报与既有数据都可能产生同样的阳性记录。

## 示例

某服务加入一条告警规则后报告“检测到 17 次利用尝试”。用同一规则回放正常流量，同样产生 17 条告警。报告未设阴性对照，把全部告警归因于攻击流量。证据支持的结论是：该规则对正常流量也会触发。告警数量与攻击行为的对应关系尚未建立。

## 识别方法

- 在与处理组相同的构建、环境与观测方法下，运行一个预期不触发的对照，并记录结果。
- 检查阴性对照的选择理由：除关键变量外，它是否与处理条件共享全部因素。
- 检查阴性对照是否出现与处理组相同的观测。出现相同观测即说明该观测量不具备区分力。
- 检查报告是否保留阴性对照的原始记录，而不是只写“未触发”。
- 最小证伪：用正常输入替换触发输入，其他条件不变；若结果相同，归因不成立。

## 预防与验收要求

- 每个因果主张必须包含至少一个阴性对照，且与处理组同构建、同环境、同观测方法。
- 阴性对照的选择必须写明理由，不得选必然不相关的样本凑数。
- 阴性对照出现阳性观测时，必须降低结论强度或更换观测量。
- 应当保留阴性对照的逐次原始记录与判定结果。
- 不得以“实际环境不存在该条件”为由省略阴性对照而不作声明。

## 验收证据与量化字段

- 处理组与阴性对照的条件差异清单。
- 阴性对照的逐次结果与观测量的判定规则。
- 两组使用同一构建、环境与观测方法的证明。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `negative_control_present` | 是否执行了预期不触发的对照 | 布尔 |
| `negative_control_matched_on` | 与处理组保持一致的项 | 集合：构建 / 环境 / 观测方法 / 输入规模 |
| `negative_control_positive_ratio` | 阴性对照出现同一观测的次数占对照总次数的比例 | % |
| `observation_specificity` | 观测量对两组的区分能力 | 枚举：仅处理组出现 / 两组均出现 / 均不出现 |
| `control_selection_basis` | 阴性对照的选择依据 | 文本 |

## 边界与关联

- 本条目是 [VXP-013](VXP-013-缺少正负对照与因果验证.md) 的子条目，继承其定义，只增加阴性对照的判据。
- 与 [VXP-013.002](VXP-013.002-缺少阳性对照.md) 的分工：本条目回答“不触发时是否也会出现”，阳性对照回答“触发时能否被看见”。
- 无法构造阴性对照时，应声明不可归因。用替代环境或时间分割作弱对照时，必须标注为弱对照。
- 阴性对照通过并不证明因果成立，仍需阳性对照与单变量隔离。与 VXP-011 的边界：扫描器共享误报来源时，多工具结果不构成独立的阴性或阳性对照。
- 与 VXP-030 的边界：同一进程内的状态污染会让阴性对照本身带上处理条件。
