## 定义

把“在固定程序中改变了参数”误认为“攻击者能够选择并执行任意命令”。命令选择自由度与参数控制是两个独立量，必须分别举证。

输入作为独立 argv 元素传入、不经 shell 解释时，参数中的元字符不改变所执行的程序，只构成参数或选项注入。输入被拼接进经 shell 解释的命令行时，命令分隔符本身就能引入另一个程序，此时应按命令注入评估，不得降级为参数注入。

## 示例

某服务以固定程序名和独立 argv 调用转换工具，用户输入只能落在输出文件名参数上。报告写“可执行任意命令”，但没有任何替换程序名的记录；证据实际支持的结论是“可控制该工具的一个参数”。

另一服务把输入拼进 `sh -c` 的命令字符串。参数中的分隔符触发第二个程序执行；同一入口出现两个语义不同的程序，命令选择自由度的证据成立。

## 识别方法

- 在能力声明中确认“执行哪个程序”由谁决定。凡写“任意命令”，必须给出记录，证明同一入口执行过至少两个语义不同的程序。
- 判断调用形态：`execve` 直接传 argv，还是经 shell 解释一段字符串。前者看程序路径能否被替换，后者看命令串本身能否被替换。
- 输入作为独立 argv 元素时，检查报告是否把它误当作命令注入；元字符不参与解释，不能据此声称存在命令选择。
- 输入进入 shell 命令串时，检查分隔符与替换语法是否被阻止；未阻止即按命令注入评估。
- 做负对照：不注入时无该效果；保持程序与命令串不变、只改参数时，效果应归因于参数。

## 预防与验收要求

- 能力声明必须写成三元组：可选命令集合、参数可控范围、执行身份。不得用“任意命令”概括未经证明的集合。
- 独立 argv 且程序固定时，必须表述为参数或选项注入，并按该受限效果评估影响。
- 输入进入 shell 解释的命令字符串且分隔符未被阻止时，必须按命令注入评估，不得降级为参数注入。
- 命令样本不得由被验收方单方面固定；评审方应当能从候选集合中抽取样本。
- 固定命令本身具有高危效果时，按该命令的真实效果评估，并注明“非命令选择自由度”。

## 验收证据与量化字段

最小证据：

- 两个及以上语义不同的程序，每个都须有原始执行记录，含请求、响应与进程 argv 或审计日志。
- 调用形态证据：argv 列表或完整的 shell 命令串。
- 执行身份证据（进程属主、服务账户或等效审计字段）。
- 未注入时的负对照记录。
- 评审方抽取命令的验证记录（若声称任意命令）。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `command_choice_cardinality` | 经证据确认可由攻击者选择的不同程序数量下界；按语义不同的程序计数 | 整数 |
| `argument_control_scope` | 外部输入可影响的参数部分 | `none` / `fixed_position` / `arbitrary_position` / `whole_string` |
| `invocation_form` | 目标程序的调用形态 | `execve_argv` / `shell_string` |
| `command_string_mutable` | 交给 shell 的命令串本身能否被外部输入改变 | 布尔 |
| `exec_identity` | 执行时的主体身份类别，不记凭据 | 字符串 |
| `challenge_sample_source` | 验证命令自由度的样本由谁选取 | `author_fixed` / `reviewer_random` |

## 边界与关联

参数注入在特定程序上可能触发外部程序，此时按参数注入的真实链评估，不直接改称任意命令。固定程序本身若接受任意路径或子命令，影响可以很高，但属于该程序的既有能力，不是命令选择自由度。

检查范围仅限命令选择自由度的描述与证据是否一致；这一范围不证明命令在目标环境必然可用，也不证明影响范围。范围问题见 VXP-020，影响类别问题见 VXP-023。
