## 定义

把链式弱点与复合弱点混为一类，用同一种验证方式处理，导致顺序可达性或并存前提被漏检。

链式弱点由两个以上弱点按顺序连接，前者直接创造后者的条件，CWE 称前者为 primary、后者为 resultant；复合弱点要求多个弱点同时成立，去掉任一分量即可阻断。混淆会同时破坏验证顺序、并存检查和映射依据。

## 示例

报告把“整数溢出导致缓冲区溢出”和“符号链接跟随需可预测性、权限与竞态同时成立”都写成“组合漏洞”，只验证第一步。错误结论：组合弱点已复现。证据支持的结论：链式部分成立，复合所需的分量未逐一确认。

## 识别方法

- 判定结构：前一弱点是否直接创造后一弱点的条件，或所有分量是否必须同时存在。
- 链式弱点是否按顺序逐环验证，并记录每环的输入与结果。
- 复合弱点是否列出全部分量，并确认在本环境中同时成立。
- 映射依据是 CWE 的 Requires、RequiredBy、命名链编号，还是分析者判断。
- 不同工具报告同一组合的不同部分时，是否按结构归并而不是重复计数。

## 预防与验收要求

- 报告标注结构类型：chain、composite 或 ambiguous。
- 链式验证按顺序记录每环；未验证的环标为未验证，不视为成立。
- 复合验证列出全部分量并逐一确认，不以“已具备条件”概括。
- 映射依据写明 CWE 编号与关系；仅有判断时标 analyst_judgment。
- 分类映射不是利用成功证明，也不能替代效果观测。
- 结构无法判定时标 ambiguous，并说明缺失信息。

## 验收证据与量化字段

最小证据：结构判定说明；链式各环或复合各分量的验证记录；CWE 映射与关系依据；工具报告的归并说明。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `weakness_structure` | 判定出的弱点结构 | `chain` / `composite` / `ambiguous` |
| `ordering_verified` | 链式顺序是否逐环验证 | `yes` / `no` / `not_applicable` |
| `co_presence_verified` | 复合分量是否确认同时成立 | `yes` / `no` / `not_applicable` |
| `mapping_basis` | 映射所依据的关系类型 | `cwe_relationship` / `named_chain` / `analyst_judgment` |

## 边界与关联

- 与 VXP-041 的分工：041 检查研究完成被当成漏洞交付；本条目检查组合结构的判定与验证方式。
- 与 VXP-017 的分工：017 检查整条链是否端到端成功；本条目先确定对象是链还是复合。
- 与 VXP-020 的分工：进程内效果与外部终局的区分不因结构判定而消失。
- 链式弱点成立不等于最终效果成立，效果仍需独立观测。
- 无子条目。
