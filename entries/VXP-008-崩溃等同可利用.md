## 定义

把一次可复现的崩溃、断言失败、未捕获异常或进程中止误认为漏洞可利用的证据，并据此宣称代码执行、权限提升或跨边界影响。崩溃只证明程序进入了错误状态，不证明攻击者控制该状态及其后果；可利用性需要另行证明错误状态能映射到安全边界另一侧。

## 示例

某服务收到畸形请求，触发空指针解引用，以非零状态退出。报告写“远程崩溃，可进一步实现代码执行”。故障地址是固定空值，输入片段与故障地址没有对应关系，报告也没有提供任何写入或控制流证据。证据支持的结论是：该输入使服务进程终止，属可用性影响；范围取决于服务是否被监督进程重启。代码执行不在证据范围内。

## 识别方法

- 对每条主张回答四个问题：崩溃点在哪，故障地址或对象由谁决定，攻击者能否影响它，影响落在哪个安全域。
- 做输入归因：只改变被认为关键的输入片段，观察故障签名是否随之变化。任意畸形输入都走同一中止路径时，该崩溃属健壮性缺陷。
- 对照评分向量与正文：向量只有可用性而正文写代码执行，即为外推。
- 检查结论是否止步于工具退出码、sanitizer 报告标题或断言文本。
- 最小证伪：去掉输入可控性这一环，结论是否仍成立。

## 预防与验收要求

- 必须分字段登记崩溃可复现性、错误状态类型、可控性证据、影响类别与未证明项。
- 不得从崩溃直接推出代码执行或提权；缺少原语证据时结论上限为可用性影响，并注明范围。
- 应当单独评估断言与未捕获异常的影响范围。CWE-248 除拒绝服务外还列有读取应用数据，作用域含机密性，不得一律按仅可用性处理。
- 声称可利用时必须提供原语级证据与跨边界观测，且不得复用同一份崩溃栈充当两项证据。
- 未获证明的环节必须逐条列出，不得用“可能进一步利用”替代。

## 验收证据与量化字段

- 脱敏后的触发输入、目标构建标识、崩溃栈、故障地址或对象类型。
- 输入归因差分记录：改变关键片段与改变无关片段的两组结果。
- 若结论含代码执行或提权：读写范围证据，以及另一安全域中的独立观测。
- 未证明项清单，逐项对应结论中被跳过的推理环节。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `crash_repro_ratio` | 独立重放中同一故障签名出现的次数占重放总数 | % |
| `fault_origin` | 故障地址或对象的来源 | 枚举：常量或空值 / 输入派生 / 堆布局派生 / 未知 |
| `input_attribution` | 关键输入与故障的因果关联方法 | 枚举：无 / 差分 / 污点或符号执行 |
| `impact_categories` | 证据支持的影响类别，可多选 | 集合：可用性 / 完整性 / 机密性 / 代码执行 |
| `availability_scope` | 可用性影响的作用范围 | 枚举：单会话 / 跨会话 / 跨租户 / 不适用 |
| `primitive_evidence_level` | 原语证据强度 | 枚举：无 / 单点观测 / 稳定原语 / 端到端 |
| `cvss_vector` | 报告给出的评分向量，用于与正文对照 | 字符串 |
| `unproven_claims` | 结论中缺少证据的推理环节数量 | 计数 |

## 边界与关联

- 远程触发且跨会话或多租户的崩溃本身即可构成拒绝服务结论，影响类别不变，不能改写为代码执行。
- 写操作落在受输入影响地址的崩溃已接近原语，此时要判断的是证据是否足够。
- 与 VXP-016 的边界：偶发崩溃属于稳定性问题。与 VXP-024 的边界：崩溃引发的重启、数据损坏与状态丢失另行计入副作用。与 VXP-013 的边界：崩溃与影响之间的因果验证属于 VXP-013 的范围。
- 满足本条的检查也不能证明目标不可利用；缺少原语证据不等于目标不可利用。
- 无子条目。
