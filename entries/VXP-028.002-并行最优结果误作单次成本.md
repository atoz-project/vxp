## 定义

把并行副本中最先返回者的耗时当作单次动作成本，同时不报告额外副本的资源消耗。父条目 VXP-028 处理成本记账边界；本条目只处理并行副本造成的资源漏计与墙钟重复计算。

## 示例

8 个副本同时发出，单副本 50 ms，首个响应到达后取消其余 7 个。报告写“成本 50 ms，与单副本相同”。墙钟确实是 50 ms，但系统承担了 8 个副本的资源。另一种错误是把 8 个副本的时长相加得到 400 ms；并行时长重叠，不能相加。

## 识别方法

- 检查并行副本数是否记录。
- 检查墙钟是否被副本数乘过，或被相加过。
- 检查资源量是否按实际执行副本数统计。
- 检查取消是否真正终止副本，未终止的副本是否计入资源。
- 最小证伪：对比单副本与多副本两次运行的资源计数。

## 预防与验收要求

- 墙钟必须按动作计一次，不得乘以或累加并行副本数。
- 资源消耗必须按实际执行副本数与 CPU 时间统计。
- 必须报告 `parallel_fanout`、`cancelled_replicas` 与 `cancelled_cpu_seconds`。
- 并行度属于实验条件，必须随结果记录。
- 具体并行度由项目验收方案定义。

## 验收证据与量化字段

- 每个副本的起止时间与取消记录。
- 单副本运行的资源计数，作为倍数基准。
- 资源采集点说明。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `parallel_fanout` | 单动作同时发出的副本数 | 个 |
| `wall_clock_per_action` | 动作起点到最终判定的墙钟 | 秒 |
| `aggregate_cpu_seconds` | 动作涉及副本消耗的 CPU 时间总和 | CPU·秒 |
| `cancelled_replicas` | 收到首个响应后取消的副本数 | 个 |
| `replicas_completed` | 正常完成且未被取消的副本数 | 个 |
| `resource_multiplier` | 聚合资源 ÷ 单副本资源 | 倍数 |

## 边界与关联

- 延迟指标与资源指标回答不同问题，必须分开报告。
- 取消不保证资源立即释放；未停止的副本仍计入资源量。
- 与 VXP-028.003 的分工：本条处理并行副本的墙钟与资源，后者处理取消或放弃后仍在执行的工作。
