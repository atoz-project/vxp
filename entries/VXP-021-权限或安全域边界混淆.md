## 定义

把不同权限级别或不同安全域中的主体与资源混为一体，误认为低权效果等于高权效果、域内效果等于跨域效果。

效果的严重程度取决于主体是谁、对象属于哪个域、两者之间是否存在强制边界。只写“可以读取”或“可以执行”而不写身份与域，读者会按最高权限或最大范围理解。

## 示例

服务账户能读取本服务的配置文件，报告写成“可读取任意敏感文件”。同一操作以普通用户和 root 分别复测时，只有 root 成功；报告没有区分两次试验的主体，也没有给出边界两侧的观测。

另一例：攻击者从普通用户提升到 root。报告按“新增的那部分权限”评分，评为较低等级。CVSS v4.0 要求只对确实发生变化的类别计分，但该类别取终局水平，而不是终局与初始的差值；此处应按 root 的最终影响取值，同时不得把利用前已有的普通用户权限重复计为新增影响。

## 识别方法

- 对每条效果标注三元组：主体身份、对象所属域、强制边界的实施点。
- 做同身份或更低权限对照：以较低权限主体重复同一操作。若失败，原结论不能跨域成立。
- 检查能力变化清单：操作前后各有哪些能力，哪些是新增，哪些在利用前已存在。
- 检查评分口径：是否只对变化类别计分，取值是否为终局水平，是否把既有权限重复计入。
- 检查设计内授权（setuid、服务账户、委托管理）是否被误记为越权。

## 预防与验收要求

- 每条效果声明必须写明主体身份、对象域和边界实施点；缺任一项不得作出跨域结论。
- 只对确实发生变化的类别计分；该类别取值按终局水平计，不得按差值计；不得把利用前已存在的权限重复计为新增影响。
- 不得把域内提升表述为跨域提升；跨域主张必须附边界穿透证据。
- 设计内授权必须标注为策略允许的行为，不得计入越权。
- 身份与域的描述不得包含凭据、令牌或可直接复用的认证材料。

## 验收证据与量化字段

最小证据：

- 主体身份与对象域的标注，以及边界实施点的配置证据。
- 同身份或更低权限身份的对照实验记录。
- 能力变化清单：操作前能力、操作后能力、新增项、利用前已存在项。
- 跨域时的双侧观测。
- 设计内授权的策略来源（如适用）。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `subject_privilege_before` | 利用前主体在目标平台等级表中的级别；平台等级表须随交付给出 | 等级标识或能力集合 ID |
| `subject_privilege_after` | 利用后同一等级表中的级别 | 同上 |
| `capability_changes` | 操作前后发生变化的能力项数 | 整数 |
| `object_domain` | 被影响对象所属的安全域 | `same_domain` / `adjacent_domain` / `external_domain` |
| `boundary_mechanism` | 分隔主体与对象的强制机制 | `none` / `os_credential` / `container` / `hypervisor` / `network_policy` / `app_authz` |
| `cross_domain_verified` | 是否以边界外侧的独立观测证实跨域 | 布尔 |
| `preexisting_privilege_excluded` | 利用前已存在的权限是否已排除在新增影响之外 | 布尔 |
| `impact_valuation` | 变化类别的影响取值口径 | `final_level` / `delta` / `not_scored` |

`adjacent_domain` 指共享同一强制边界实施点、但策略不同的相邻域；`external_domain` 指由独立强制边界实施点约束的域。平台没有有序等级时，记录能力集合，不得伪造等级次序。`impact_valuation` 中的 `delta` 与 `not_scored` 用于记录不符合本条要求的口径，不是可选方案。

## 边界与关联

对象与主体同属一个 system of interest 且策略一致时，域内效果就是全部效果，不应增加跨域叙述。设计内授权在策略上合法，但应作为配置事实记录，不等于没有风险。

通过本页检查只证明身份与域的归属描述正确，不证明边界在所有部署形态下有效。利用前权限是否披露见 VXP-006，缓解绕过是否披露见 VXP-018，范围外推见 VXP-020。

无子条目。
