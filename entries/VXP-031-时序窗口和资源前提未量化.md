## 定义

竞争窗口与资源水位未测量，却被当作已知前提。结论依赖检查事件到使用事件之间的间隔、动作自身从发起到生效的时长、两者的抖动，或可用内存、CPU 配额、队列深度。这些量没有随结果记录。

窗口与动作时长是两个量。`window_gap` 是检查事件结束到使用事件开始的可观测间隔；`action_duration` 是动作从发起到生效的时长。把动作时长并入窗口，会使测量值随测试者动作快慢变化。成功条件应表述为 gap 与 action_duration 的比较，并计入抖动。

## 示例

报告称“窗口足够大”。测量显示 gap 中位数 2 ms，动作时长 5 ms，抖动约 1.5 ms。按中位数，动作在窗口关闭后才生效。只有 gap 的右尾与动作时长的左尾重叠时才可能成功。缺少这三个量，无法判断结论属于哪种情况。

## 识别方法

- 检查 window_gap 两端各对应哪个可观测事件，用什么时钟测量。
- 检查 action_duration 是否单独测量，是否与 gap 同单位、同时钟。
- 检查 timing_jitter 是否给出分布，而非单一典型值。
- 检查资源记录：可用内存、CPU 配额、并发度、队列深度是否每次采集。
- 检查是否做过资源扰动实验：只改一项资源，观察成功率是否变化。
- 最小证伪：保持代码不变，仅收紧一项资源限制后复跑；结论翻转且无记录即说明前提未量化。

## 预防与验收要求

- 必须分别测量 `window_gap`、`action_duration` 与 `timing_jitter`，不得用一个合成窗口值替代。
- 成功判据必须写成 gap 与 action_duration 的比较，并说明抖动如何处理。
- 必须记录运行时资源包络：可用内存、CPU 配额或限制、并发度与队列深度，注明采集点与单位。
- 必须报告从开始尝试到首次成功的尝试次数分布，以及单次尝试的成功比例。
- 资源限制必须作为实验条件归档。改变限制值视为新条件，不得与旧数据合并。
- 应当至少在两个资源水平下重复实验。具体窗口上限与资源数值由项目验收方案定义。

## 验收证据与量化字段

- 窗口与动作的测量记录：起止事件、时钟、样本、分布。
- 每次运行的资源快照。
- 尝试次数到首次成功的分布。
- 至少一组资源扰动对照结果。

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `window_gap` | 检查事件结束到使用事件开始的可观测间隔 | 秒 |
| `window_method` | gap 的测量方法 | 枚举：插桩/外部观测/推算 |
| `action_duration` | 动作从发起到生效的时长 | 秒 |
| `timing_jitter` | gap 或动作时长的抖动，以分位数或极差表示 | 秒 |
| `timing_source` | 计时所用时钟与观测点 | 字符串 |
| `attempts_to_first_success` | 从开始尝试到首次成功的尝试次数 | 次 |
| `p_success_per_attempt` | 单次尝试的成功比例 | 比值 |
| `mem_available` | 运行时可用的内存量 | 字节 |
| `mem_peak` | 运行期间的峰值内存占用 | 字节 |
| `cpu_quota` | CPU 配额或限制值 | 核数或配额单位 |
| `cgroup_limit_ref` | 生效的限制配置标识 | 字符串 |
| `queue_depth` | 观测到的排队请求数 | 个 |
| `load_level` | 运行时的系统负载指标 | 无量纲 |

## 边界与关联

- 窗口估计依赖硬件、调度器与负载，是条件量。报告必须绑定环境。
- 资源充足时窗口可能无法稳定测量，应报告“未能测得”及测量下限。
- 量化前提不等于宣称可利用性。窗口与资源满足只是必要条件。
- 本条目不判断顺序与状态污染，见 VXP-030。本条目不判断计时边界与时钟，见 VXP-029。
- 无子条目。
