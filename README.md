# 漏洞验证指南

VXP（Vulnerability Validation Guide）记录漏洞研究、验证和交付中常见的证据误判，帮助团队把技术结论建立在可复核的证据上。分类定位场景，条目给出判断依据与检查方法；具体验收标准由项目约定。

## 使用方式

分类（A～F）按研究与验证活动组织，帮助你定位场景。主条目（`VXP-NNN`）描述一种可独立判断的误判；子条目（`VXP-NNN.MMM`）补充独立场景、判据或证据要求；原子条目直接给出完整检查方法。完整定义见[术语表](GLOSSARY.md)，编写与编号规则见[模板](TEMPLATE.md)。

通用条目提供判断框架；次数、比例、容差与时限由具体项目约定，并在条目中明确标注。编号保持稳定，定义变化时新增条目并标注关系。

参考来源用于支撑技术事实；条目中的“必须”“应当”若属于项目约定，会明确标注。

- 阅读站点：<https://atoz-project.github.io/vxp/>
- 术语表：[GLOSSARY.md](GLOSSARY.md)
- 条目契约：[TEMPLATE.md](TEMPLATE.md)
- 字段表：`_data/entry_record.yml`（检查器与站点共用的唯一 schema）
- 条目文件：`entries/VXP-NNN-短标题.md`。文件顶部的 front matter 是条目记录，保存编号、标题、分类、父条目、状态、版本与日期。

```sh
uv run bin/check-entries
uv run --with pyyaml python -m unittest discover -s tests
```

分类名称、目录、计数和侧栏由站点在构建时从条目记录生成，本文件保留仓库入口与维护说明。新增条目先读 [TEMPLATE.md](TEMPLATE.md)。

## 维护规则

1. 新增条目前，先确认它是否属于现有条目的示例；出现独立判据或证据要求时再拆分。
2. 子条目继承父条目的共同规则，正文只写新增内容；父条目保留导航和共同边界。
3. 删除或合并条目时保留旧 ID 的重定向说明，并标注新旧关系。
4. 每个事实性技术结论附可访问的一手来源；暂时无法核验的内容标注为未验证。
5. 项目映射记录条目状态、证据链接、责任人和复核日期；私有映射保留在项目内部。

## 条目元数据与版本

- **条目版本**：采用 `主版本号.次版本号.修订号`，初始公开草案为 `0.1.0`。
- **创建日期**：条目首次建立的日期，发布后保持固定。
- **修改日期**：条目正文、判据、字段或来源发生实质修改的日期；批量修改时同步更新。
- **参考来源查询日期**：保留在每条来源后，表示在线资料的访问时间；它与条目修改日期分别记录。
- **修订号（PATCH）**：用于文字、格式或来源说明修正，判据保持不变。
- **次版本号（MINOR）**：增加向后兼容的示例、检查方法、量化字段或子条目。
- **主版本号（MAJOR）**：在条目范围不变的前提下调整判据或字段语义；条目范围发生根本变化时，新增 ID 并保留原条目。
